# Building the Lamp Room

Everything here is for whoever works on the app. None of it loads in the app itself.

## Rules that don't bend

- **No real business data in this repo.** No manuscripts, no L&L export, no planner data, no recordings. Tests use made-up books only (`fixtures/`).
- **No keys or emails.** API keys, tokens and personal email addresses never go in a file here.
- **Ask before removing a feature.** Agree a plan before bigger changes.

## Layout

| Folder | What's in it |
|---|---|
| `tests/` | Browser tests, `e2e<N>.py`. Each opens the app in a hidden Chrome with `?test`, which keeps everything in browser storage and uses a fake microphone. |
| `fixtures/` | Made-up sample files: small .docx/.pdf manuscripts, scripts and their generators. WAVs are generated by `make_fixtures.py` and not committed. |
| `tools/build_booth.py` | Joins `js/booth/*.js` into `js/booth.js`. `--check` says whether the join is current. |
| `tools/stamp.py` | Updates the `?v=` stamp on every script and stylesheet so browsers pick up the new files. Run it before every publish. |
| `tools/mkpdf.py` | Rebuilds the guide PDFs from `guide/src` (Mac and PC editions). |

## The Booth is edited in parts

`js/booth.js` is **generated**. Edit the parts in `js/booth/` (00-open … 12-cast-pickups, each headed with what it holds), then run `python3 dev/tools/build_booth.py`. The parts are pieces of one closed block of code joined in name order, so any function can call any other, as before; a part on its own isn't a complete script. `stamp.py` builds before stamping, and the test runner stops if the join is stale.

## Running the tests

```
pip install playwright pypdf python-docx
python3 dev/run_all.py              # everything, four at a time (LR_JOBS to change)
python3 dev/run_all.py e2e30 e2e33   # just those
```

A test fails if the page threw an error, the script crashed, or its own `ERR:` list isn't empty. A failure in the crowd is retried once on its own; "passed on its own" means the machine was busy, not that something broke. Logs: `/tmp/lr-<test>.log`; screenshots go to `LR_SHOTS` (default `/tmp/lr-shots`). Chrome path: `LR_CHROME`.

Writing a new test: copy a short one (e2e38 or e2e40), start with `from _env import *`, give it port `8600 + N` so parallel runs don't collide, and use `FIX + "/file"` for samples. Test hooks live on `Booth._test`, which only exists in `?test` mode.

## Publishing

1. `python3 dev/run_all.py` — all green.
2. Add a line to the top of `js/news.js` for anything people will notice, tagged with who it matters to (`all`, `team`, `narrator`, `cast`, `editor`). It shows once on their Dashboard.
3. **Once per batch** (not every fix): `python3 dev/tools/mkpdf.py` if the help text or keys changed. Each rebuilt PDF adds a full copy to the repo's history, so batch them.
4. `python3 dev/tools/stamp.py`
5. Commit, push to `main`. GitHub Pages serves it within a minute or two; check the live site.

## Problems from the field

Settings ▸ Problem log on any computer keeps the last 100 errors, failed saves and "couldn't…" messages. **Copy for Claude** puts them on the clipboard with the version stamp, so you can match them to a commit.
